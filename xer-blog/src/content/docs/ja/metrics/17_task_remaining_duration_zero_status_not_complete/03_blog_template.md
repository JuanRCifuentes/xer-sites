# ステータスが完了していない間、タスクの残り期間がゼロになる

残り期間は、Primavera P6 アップデートで最も重要なステータス フィールドの 1 つです。アクティビティを完了するまでにどのくらいの時間が必要かをスケジュールに通知します。通常のタスク アクティビティの残り期間が 0 の場合、メッセージは単純です。実行する時間が残っていないということです。同じタスクが完了としてマークされていない場合、スケジュールは 2 つの異なるストーリーを同時に伝えていることになります。

このメトリクスは、残り期間が 0 であるが、タスクのステータスが完了ではないタスク アクティビティを識別します。これは、より広範なステータス品質チェックの焦点を絞ったバージョンです。タスク アクティビティでは、この不一致が作業計画、進捗レポート、獲得価値、および先読みレビューに直接影響を与える可能性があるためです。

通常のタスクの場合、残り期間がゼロになると、作業が完了したことを意味します。アクティビティには、プロジェクトの更新手順と一致する実際の終了、完了ステータス、および進行状況の値が含まれている必要があります。タスクがまだ進行中または未開始の場合、ある程度の作業量がまだ予想されるため、通常、残り期間は 0 より大きくなります。

この問題は、更新サイクルが忙しいときによく発生します。フィールド チームは、アクティビティが効果的に完了したと報告する場合があるため、スケジューラは残り期間を 0 に減らしますが、実際の終了には入りません。インポート ファイルは、アクティビティ ステータスを更新せずに残り期間を更新する場合があります。手動更新では進行状況の値が設定されても、アクティビティが間違ったステータスのままになる場合があります。その結果、期間の観点からは完了しているように見えますが、ステータスの観点からは未完了のタスクが作成されます。

その矛盾こそが重要なのです。残り期間のないタスクでは、今後の作業が期待どおりに実行されなくなる可能性があります。正式には完成していなくても、先読み注目から消える可能性があります。進捗状況と完了状況が一致していない場合、獲得価値レポートが歪められる可能性があります。また、スケジュールではタスクが完了したかどうかを明確に回答できないため、クライアントまたは PMO のレビュー中に混乱が生じる可能性があります。

レビューは単純な P6 レイアウトから始める必要があります。アクティビティ ID、アクティビティ名、WBS、アクティビティ タイプ、アクティビティ ステータス、実際の開始時間、実際の終了時間、元の期間、残りの期間、完了期間、完了率タイプ、アクティビティの完了率、開始、終了、および合計フロートが含まれます。残り期間が 0 で、アクティビティ ステータスが完了ではないタスク アクティビティをフィルターします。

フラグが立てられた各タスクは、責任ある所有者と一緒にレビューする必要があります。本当に工事は終わっているのでしょうか？ 「はい」の場合、タスクには通常「完了」のマークが付けられ、正しい「実際の終了」が与えられるはずです。スケジューラは、完了率と残りの期間がプロジェクトの進行ルールに従っていることも確認する必要があります。

作業が完了していない場合、修正方法は異なります。タスクは進行中や未開始などの正しいステータスを維持する必要がありますが、残りの期間は有効な値に復元される必要があります。この値は、目標終了日やレポート設定ではなく、データ日の時点での残りの作業を反映する必要があります。

「火災警報装置の設置」というタスクについて考えてみましょう。フィールド レポートでは、インストールがほぼ完了し、スケジューラが残りの期間を 0 に設定していると報告されています。しかし、テストの結果、いくつかのデバイスはまだ修正が必要であることが判明し、実際にはデータ日付までにアクティビティが完了していませんでした。この場合、タスクの残り期間がゼロのままであってはなりません。スケジュールが未完了の作業を予測し続けるように、残りの作業量を見積もって入力する必要があります。

ここで、「レベル 3 スラブの注入」というタスクについて考えてみましょう。コンクリートの注入はデータ日付より前に完了しましたが、アクティビティはまだ「進行中」と表示され、実際の終了はありません。ここで、残り期間 0 はおそらく正しいですが、ステータスの更新は不完全です。スケジューラは実際の終了を入力し、タスクに完了のマークを付ける必要があります。

このメトリックの目標しきい値は、未解決のタスク アクティビティがゼロである必要があります。未解決という言葉は重要です。一部の項目は修正前に現場での確認が必要な場合がありますが、報告スケジュールで説明されないままにするべきではありません。一時的な更新理由がある場合は、各項目を修正するか、所有者に割り当てるか、文書化する必要があります。

この指標は、更新規律の改善にも役立ちます。サイクルごとに同じ問題が発生する場合、チームはインポート マッピング、更新フォーム、フィールド レポート手順、およびスケジュールの問題の前にチェックを確認する必要があります。ユーザーは、アクティビティを適切に完了せずに、進行状況を表示する最も速い方法のように感じて、残り期間を 0 に設定している可能性があります。

この指標をクリーンアップすると、スケジュールが信頼しやすくなります。残りの期間、アクティビティのステータス、実際の終了日、進捗状況の値を調整します。さらに重要なことは、プロジェクト チームがどの作業が本当に完了し、どの作業がまだ注意が必要であるかについて、より適切な決定を下すのに役立ちます。
