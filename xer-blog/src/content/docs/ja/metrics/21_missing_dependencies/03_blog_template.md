# Primavera P6 で不足している依存関係

依存関係は CPM スケジュールのバックボーンです。作業が 1 つのアクティビティから次のアクティビティにどのように移行するか、作業を開始する前に何が必要か、各アクティビティの完了に何が依存するかについて説明します。依存関係が欠落している場合でも、スケジュールは計算される可能性がありますが、結果は信頼できなくなります。

このメトリクスは、Primavera P6 で依存関係ロジックが欠落しているアクティビティを特定します。これには、先​​行者のいないアクティビティ、後続者のいないアクティビティ、およびそのどちらもない孤立したアクティビティが含まれます。これらは、オープン スタートおよびオープン フィニッシュと呼ばれることがよくあります。いくつかは有効かもしれませんが、ほとんどは見直す必要があります。

先行タスクのないアクティビティは、以前の作業からの論理的な要件なしで開始できます。これは、承認されたプロジェクト開始マイルストーンまたは外部から承認された開始については許容される可能性があります。通常のプロジェクト作業では、これは通常、警告サインです。建設、エンジニアリング、調達、テスト、引き渡しの活動は、通常、アクセス、設計リリース、材料の納品、事前の設置、検査、許可の承認、またはその他のプロジェクト条件などの何かに依存します。

後続のないアクティビティは、その結果を他のアクティビティに渡さずに終了できます。これは、プロジェクトの最終完了マイルストーンとしては許容できるかもしれません。しかし、ほとんどのアクティビティでは、質問は単純です。この作業によって何が可能になるのでしょうか?何も依存していない場合、アクティビティには後続ロジックがないか、時代遅れであるか、スケジュールに適切に統合されていない可能性があります。

孤立した活動が最も明らかな懸念です。アクティビティに先行アクティビティと後続アクティビティがない場合、そのアクティビティは実際には CPM ネットワークの一部ではありません。ファイルに保存され、日付が記載され、レポートに表示されることもありますが、スケジュールが作業の順序を説明するのには役立ちません。

依存関係の欠落は、ロジック品質スコア以上の影響を与えます。開始日、終了日、浮動小数点値、クリティカル パスが歪む可能性があります。オープンスタートは、何も妨げるものがないため、データ日付にずれたり、開始が早すぎたりする可能性があります。オープン仕上げでは、プロジェクトの残りの部分に対する作業の影響を反映しない浮きが発生する場合があります。 PMO またはクライアントのレビュー中に、これらのギャップにより、日付がなぜ信頼できるのかを説明することが難しくなります。

実際のレビューは、アクティビティ ID、アクティビティ名、WBS、アクティビティ タイプ、アクティビティ ステータス、開始、終了、合計フロート、カレンダー、制約、先行タスク、後続タスクを含む P6 レイアウトから始まります。先行者も後続者も、どちらも存在しないアクティビティをフィルターします。次に、有効な例外を修正が必要な項目から分離します。

有効な例外は制限されるべきです。承認されたプロジェクトの開始には先行者が必要ない場合があります。最終的な完了マイルストーンには後続者が必要ない場合があります。一部の外部インターフェイスのマイルストーンは、スケジュール外で制御される作業を表す場合があります。これらの例外は、レビュー担当者が推測する必要がないように文書化する必要があります。

オープン スタートの場合は、作業を開始する前に必要な実際の状態を反映する先行ロジックを追加します。これは、以前の建設活動、設計の承認、材料の納品、アクセスの解放、検査、許可、またはインターフェースの引き継ぎなどである可能性があります。関係は、チェックに合格するためにアクティビティを接続するだけでなく、実際の依存関係を記述する必要があります。

オープン フィニッシュの場合は、後続の内容を表す後続ロジックを追加します。後続は、別の作業活動、テスト、試運転、売上高、完了、マイルストーン、または下流パッケージである可能性があります。重要なのは、アクティビティの結果が計画の残りの部分にどのような影響を与えるかを示すことです。

分離されたアクティビティの場合は、まずそのアクティビティがまだ必要かどうかを確認します。有効なスコープであれば、正しく接続してください。古いアップデート、重複したアップデート、または古いアップデートから残っているアップデートがある場合は、プロジェクト管理手順に従って削除または閉じてください。

目標のしきい値は、未解決のアクティビティがゼロである必要があります。これは、欠落しているすべての先行者または後続者が自動的に間違っているという意味ではありません。つまり、すべての例外は意図的に文書化されなければなりません。原因不明の依存関係が欠落していると、スケジュール ネットワークが弱体化します。

このメトリックをクリーンアップすると、スケジュールがすぐに改善されます。これにより、クリティカル パスの信頼性が高まり、フロートの解釈が容易になり、先読み計画がより便利になります。また、プロジェクト チームが、そのスケジュールが実際の作業モデルなのか、それとも単に日付が記載されたアクティビティのリストなのかを確認するのにも役立ちます。
