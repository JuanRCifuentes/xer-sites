# 关键路径

关键路径是进度计划中最长的相关活动序列。它决定了项目的最短持续时间，并直接定义了项目完成日期。

实际上，关键路径是在不影响最终期限的情况下不能延迟的任务链。如果关键路径活动发生延误并且其他任何事情都没有发生变化，那么项目完成日期也会延误。

这就是为什么关键路径是 Primavera P6 计划最重要的输出之一。它不仅仅是一个过滤器、一种颜色或一份报告。这是进度计划对推动完成的因素的解释。

## 关键路径意味着什么

进度计划表包含许多活动，但并非所有活动对完成日期都有相同的影响。有些活动有浮时。在影响下一个活动或项目完成之前，他们可以稍微移动一下。关键活动不具有这种灵活性，或者根据计划方法和设置，它们具有最小的灵活性。

关键路径显示根据当前逻辑、持续时间、日历、约束和状态完成项目所需的最短时间。

```mermaid
flowchart LR
    A["项目启动"] --> B["设计发布"]
    B --> C["采购长周期设备"]
    C --> D["安装设备"]
    D --> E["佣金制度"]
    E --> F["项目完成"]
```

如果这是控制链，采购的延迟可能会延迟安装。安装延迟可能会延迟调试。调试的延迟可能会延迟项目的完成。关键路径可以帮助团队看到这种联系。

## 这是你不能拖延的链条

关键路径不仅仅是感觉重要的工作。定义完成日期的是工作的相关顺序。

这种区别很重要。如果一项高价值活动具有流动性，那么它可能并不重要。如果有其他路径正在推动完成，那么可见的客户里程碑可能并不重要。如果一项小型技术活动位于导致最终移交的唯一链中，则它可能至关重要。

对于项目控制团队来说，这使得关键路径成为决策工具。它有助于回答：

- 是什么推动了项目的完成？
- 哪些活动最需要进度计划编制关注？
- 哪里的延迟会立即影响完成？
- 哪些恢复措施可以保护完成日期？
- 报告的路径有意义吗？

最后一个问题是进度计划人员永远不应该跳过的问题。

## 不要盲目接受关键过滤器

Primavera P6 可以识别关键活动，但该软件无法理解项目意图。它根据提供的数据进行计算：逻辑、日历、约束、持续时间、进度和计划选项。

如果数据薄弱，关键路径可能看起来很奇怪。

活动或里程碑可能会出现在关键过滤器中，即使它们并没有真正推动项目。发生这种情况的原因包括逻辑缺失、硬约束、过时的日期、开放式结尾、不寻常的日历、负浮时、不正确的状态或保留的逻辑设置。

进度计划者必须使用专业判断。关键路径应该受到挑战。看起来应该是有道理的。它应该讲述一个项目团队认可的故事。

如果路径表明最终完成是由行政里程碑驱动的，没有真正的下游工作，请挑战它。如果路径以一个实际上并不控制执行的里程碑开始，那就挑战它。如果路径跨越不相关的 WBS 区域且没有清晰的界面，请对其提出质疑。

关键路径的好坏取决于其背后的进度模型。

## 基线进度计划和关键路径

在从未更新过的计划中，例如第一个基线，关键路径通常从项目开始里程碑开始，到项目完成里程碑结束。

这很常见，但这并不是一成不变的规则。

有些项目有一条从关键中间里程碑开始的关键路径。例如，在业主移交一块区域、发放许可证或设计包达到批准状态之前，施工可能无法开始。在这种情况下，切换或释放里程碑可能会触发控制路径的开始。

同样的想法也适用于项目接近尾声时。关键路径可能会在最终完成时完成，但它也可能会推动中间合同里程碑、移交阶段、系统周转或目前更具限制性的客户访问日期。

关键不在于路径是否在最传统的地方开始和结束。关键是路径是否合乎逻辑、是否完整、是否站得住脚。

## 进行中的进度计划

一旦计划开始实施，关键路径就会发生变化。已完成的工作不应再推动未来的完成。该路径应从当前状态边界开始。

在更新的计划中，关键路径通常从当前正在进行的活动、准备开始的未开始活动或控制对未来工作的访问的有效里程碑开始。当该事件真正推动下一个关键工作时，它也可能从项目界面或移交里程碑开始。

这就是数据日期的重要性。数据日期将实际绩效与预测工作分开。数据日期之后的关键路径应解释剩余工作如何完成。

如果路径以没有驱动逻辑的活动开始、无法解释的数据日期开始或有问题的里程碑，则审核者应该进行调查。进度计划可能显示了一条计算出的路径，但并不可信。

## 小心里程碑

里程碑很有用，因为它们标记了关键点：进行通知、区域移交、设计批准、机械完成、系统周转、实质性完成和最终完成。

但里程碑也可能会误导关键路径审查。

里程碑可能显得很重要，因为它有限制。它可能看起来很关键，因为它没有持续时间并且位于日期边界。它可能显得很关键，因为它周围缺少逻辑。这并不自动意味着里程碑确实是控制执行链的一部分。

当关键路径以里程碑开始时要格外小心。问：

- 这个里程碑是否代表了真正的控制事件？
- 什么活动或外部条件推动了里程碑？
- 里程碑发布了哪些作品？
- 里程碑是受约束的而不是逻辑驱动的吗？
- 如果里程碑逻辑得到纠正，该路径仍然重要吗？

如果里程碑不能控制工作，就不应该允许它定义关键路径的故事。

## 保留的逻辑可以改变故事

保留逻辑是 Primavera P6 设置，用于处理无序进度。它可能是适当的，但它也可能以审阅者需要理解的方式影响关键路径。

当使用保留逻辑时，即使后续工作已经不按顺序开始，P6 也可以保留前导逻辑。这可能会导致剩余工作被保留或以改变计算的关键路径的方式排序。

问题不在于保留的逻辑总是错误的。问题是进度计划人员必须了解它是否生成了现实的预测。

如果保留的逻辑使关键路径贯穿不再反映工作执行方式的关系，则团队应检查状态、逻辑和计划选项。路径应该反映一个可防御的剩余计划，而不仅仅是机械计算。

## 如何审视关键路径

良好的关键路径审查应将 P6 输出与进度计划判断结合起来。

首先生成最长路径或关键路径报告。然后逐个查看路径活动。查看前置活动、后续、逻辑关系类型、滞后、约束、日历、实际日期、剩余持续时间和总浮时。

询问路径是否有意义：

- 该路径是否遵循可信的执行顺序？
- 它是否从有效的当前置活动动程序开始？
- 它是否在正确的完成或控制里程碑上完成？
- 约束是否迫使路径发生变化？
- 缺失的关系是否隐藏了真正的驱动力？
- 保留的逻辑是否以误导性的方式影响路径？
- 项目团队是否认为这是控制工作？

如果答案是否定的，则需要先审查进度计划，然后才能放心地使用关键路径。

## 结论

关键路径是定义项目完成日期的相关任务的序列。它显示了完成项目所需的最短时间，并确定了在不影响截止日期的情况下不能拖延的工作。

但关键路径并不是盲目接受的。 P6 计算数据告诉它要计算的内容。进度计划人员必须质疑结果是否合理、符合逻辑、是否与真实的执行计划保持一致。

在一个强有力的进度计划中，关键路径讲述了一个清晰的故事。它从有效的当前置活动动程序开始，遵循真正的依赖关系，避免误导性约束，正确处理进度，并导致正确的完成里程碑。

当这个故事有意义时，关键路径就成为项目控制中最强大的工具之一。如果没有，则表明需要对进度计划进行更多审查才能信任预测。
