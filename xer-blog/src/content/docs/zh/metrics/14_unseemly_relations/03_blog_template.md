关系逻辑是进度计划表中最容易快速复制的部分之一，也是以后最难捍卫的部分之一。在 P6 表中，关系可能看起来无害，但双方的活动类型都很重要。当一项是开始里程碑、完成里程碑或努力级别活动时，两项正常任务活动之间有意义的关系可能会显得尴尬或具有误导性。

该指标重点关注不恰当的关系：应审查的关系模式，因为它们通常与活动类型的进度计划目的不匹配。我们的目标不是自动拒绝每一种不寻常的关系。目标是在影响里程碑日期、浮时、关键路径报告或客户信心之前找到需要重新审视的逻辑。

第一组发现涉及完成里程碑。完成里程碑代表完成事件。它通常用于标记已实现包、阶段、移交、批准或合同点。当完成里程碑具有 SS 或 SF 后续活动时，逻辑可能是说稍后的活动可以因为完成事件已开始而开始，或者可以因为完成事件开始而完成。这通常很难解释。 SS 前置活动的完成里程碑也可能是可疑的，因为里程碑的完成可能与先前工作的开始相关，而不是实际证明里程碑已达到的完成条件。

第二组涉及开始里程碑。开始里程碑代表事件、阶段、访问窗口或授权的开始。如果开始里程碑有 FF 或 SF 前置活动事件，则开始事件可能会以未清楚描述所需启动条件的方式与前置活动完成事件相关联。如果开始里程碑有 FS 或 FF 后续活动，则该里程碑可能会充当任务完成点而不是开始事件。有时会发生这种情况，因为里程碑类型选择不正确。其他时候，逻辑关系类型是从进度计划表的另一部分复制的，并且从未经过审查。

第三组涉及 LOE 活动。 LOE 活动用于表示支持、监督、管理、检查或跨越其他工作的其他努力。它们通常并不像正常任务那样驱动离散的生产活动。当 LOE 活动具有 FS 或 SF 关系时，进度审核者应询问 LOE 是否正在控制应由实际工作活动、访问限制、批准或合同里程碑驱动的工作。

在实践中，这个指标很有用，因为它迫使人们就意图进行干净的对话。这个里程碑意味着什么？这个 LOE 是总结工作还是推动工作？这种关系是否描述了真实的排序，或者只是为了让约会表现得更好？

考虑称为“机械完成”的完成里程碑。如果它有“开始调试”的 SS 后续活动，则该进度计划可能意味着调试可以在机械完工开始时开始。这不太符合里程碑的概念。如果调试可以在部分周转后开始，更好的解决办法可能是添加离散的周转活动或更具体的里程碑。如果调试确实依赖于完整的机械完成，那么从完成里程碑到调试的 FS 关系就更容易理解和维护。

现在考虑一个名为“项目管理支持”的 LOE 活动，它与施工活动具有 FS 关系。这种关系可能会使支持活动成为现场工作的驱动力，但这通常不是目的。进度计划员应检查施工活动是否应由工程、采购、访问、许可、前期施工或其他离散条件驱动。 LOE 可能需要不同的开始和结束驱动程序，因此它可以跨越工作而不会错误地控制它。

最好的复习方法很简单。构建一个 P6 布局，显示活动 ID、活动名称、活动类型、前导、后续、逻辑关系类型、滞后、开始、完成、总浮时以及关键或最长路径状态。筛选里程碑和 LOE 活动，然后隔离指标标记的关系模式。首先审查关键和近乎关键的项目，因为这些项目可能会立即影响项目报告。

并非每个标记的项目都会出错。有些项目有客户特定的逻辑规则或不寻常的报告要求。一些计划模型使用特殊的里程碑来与其他系统交互。这些案例应该很少见、得到批准并记录在案。如果审阅者无法用简单的进度计划语言解释这种关系，则可能需要更正。

该指标的一个很好的目标是零未解决的关系。重要的一句话还没有解决。计划团队应该纠正关系、修改活动类型、添加更好的活动来代表真实情况，或者记录批准的例外情况。不解释这些关系会削弱进度计划，因为它使逻辑网络更难信任。

不合时宜的关系通常是较大进度质量问题的小症状：复制逻辑、不清楚的里程碑定义、误用 LOE 活动或通过逻辑关系类型强制确定日期的习惯。清理它们提高的不仅仅是指标分数。它使进度计划更容易审查、更容易解释，并且对于 PMO 治理和项目决策来说更可靠。
