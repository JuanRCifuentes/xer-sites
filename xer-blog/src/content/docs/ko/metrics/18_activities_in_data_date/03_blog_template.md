# 데이터 날짜의 활동

데이터 날짜는 Primavera P6 공정표에서 가장 중요한 날짜 중 하나입니다. 실제 성과와 미래 예측 사이의 경계를 표시합니다. 데이터 날짜 이전의 작업 상태를 알려야 합니다. 데이터 날짜 이후의 작업을 예측해야 합니다. 많은 활동이 데이터 날짜에 정확하게 조기 시작 또는 조기 종료되는 경우 일정을 자세히 살펴볼 가치가 있습니다.

이 메트릭은 조기 시작이 데이터 날짜와 같거나 조기 완료가 데이터 날짜와 같은 활동을 확인합니다. 데이터 날짜의 모든 활동이 잘못되었다고 말하는 것이 목적은 아닙니다. 일부 작업은 업데이트 경계에서 합법적으로 시작되거나 끝날 수 있습니다. 목적은 경계에서 클러스터링을 식별하고 각 활동이 그곳에 존재하는 타당한 이유가 있는지 확인하는 것입니다.

전임 작업이 완료된 후 단기 작업을 시작할 준비가 되면 데이터 날짜의 조기 시작이 합리적일 수 있습니다. 경고 신호일 수도 있습니다. 활동에 선행 로직, 비주도 로직, 제약조건, 예상 날짜 또는 불완전한 상태 업데이트가 누락되어 데이터 날짜에 있을 수 있습니다. 시작되지 않은 활동이 데이터 날짜에 많이 있는 경우 일정은 필수 조건이 모델링되지 않은 경우에도 작업을 시작할 준비가 되었음을 암시할 수 있습니다.

데이터 날짜의 조기 완료는 두 가지 다른 이야기를 말해 줄 수도 있습니다. 업데이트 경계에서 완료될 것으로 올바르게 예측되는 작업이 표시될 수 있습니다. 그러나 진행 상황이 완전히 업데이트되지 않았음을 나타낼 수도 있습니다. 작업이 실제로 데이터 날짜 이전이나 데이터 날짜에 완료된 경우 활동에 실제 완료가 필요할 수 있습니다. 작업이 완료되지 않은 경우 잔여 기간 및 예상 완료를 업데이트해야 할 수 있습니다.

실용적인 리뷰는 간단한 P6 레이아웃으로 시작됩니다. 활동 ID, 활동 이름, WBS, 활동 상태, 조기 시작, 조기 완료, 시작, 완료, 실제 시작, 실제 완료, 잔여 기간, 총 부동 시간, 달력, 제약조건, 선행 작업 및 후속 작업을 포함합니다. 그런 다음 데이터 날짜와 동일한 조기 시작 및 데이터 날짜와 동일한 조기 종료를 필터링합니다.

첫 번째 질문은 상태입니다. 활동이 완료되었습니까, 진행 중입니까, 아니면 시작되지 않았습니까? 실제 일자나 잔여 기간이 잘못된 경우 로직을 변경하기 전에 상태를 수정하세요. 상태 데이터가 좋지 않은 일정은 신뢰할 수 있는 예측 날짜를 생성할 수 없습니다.

두 번째 질문은 논리입니다. 활동이 유효한 선행자 및 후임자 관계에 의해 데이터 날짜까지 진행되고 있습니까? 선행 작업, 약한 논리 또는 비주도 관계가 없는 경우 데이터 날짜가 공개 시작 또는 공개 종료를 마스킹할 수 있습니다. 수정 사항은 활동을 수동으로 이동하는 것이 아니라 실제 공정표 로직를 추가하거나 수정하는 것입니다.

세 번째 질문은 제약조건, 예상 날짜 또는 달력이 결과에 영향을 미치는지 여부입니다. 시작 제약, 종료 제약, 오래된 예상 날짜 또는 비정상적인 달력으로 인해 활동이 업데이트 경계로 당겨질 수 있습니다. 이들 중 일부는 유효할 수 있지만 의도적이고 문서화되어야 합니다.

데이터 날짜가 4월 30일인 프로젝트를 생각해 보세요. 일련의 전기 활동은 모두 4월 30일에 조기 시작을 보여줍니다. 선행 공사가 완료되고 해당 지역이 해제된 경우에는 유효할 수 있습니다. 그러나 이러한 활동 중 일부에 선행 작업이 없거나 제약조건에 의해 제어되는 경우 일정은 진정한 논리 기반 계획을 표시하지 않습니다.

이제 4월 30일에 조기 완료되고 상태가 진행 중인 활동을 생각해 보세요. 업데이트 마감 시간까지 작업이 완료된 경우 스케줄러는 실제 완료를 입력하고 활동을 완료로 표시해야 합니다. 작업에 아직 며칠이 남아 있는 경우 예측 완료가 데이터 날짜 이후로 이동하도록 잔여 기간을 업데이트해야 합니다.

이 측정항목의 목표 임계값은 설명할 수 없는 활동이 없어야 합니다. 그 표현이 중요합니다. 목표는 데이터 날짜의 모든 활동을 제거하는 것이 아닙니다. 목표는 각 항목이 현재 상태, 유효한 논리 또는 승인된 예외로 설명되는지 확인하는 것입니다.

이 측정항목은 업데이트 검토 중에 특히 유용합니다. 데이터 날짜가 앞으로 이동한 후 일정이 완전히 상태화되지 않았거나 논리가 약한 경우 활동이 경계에서 수집될 수 있습니다. 데이터 날짜에 대한 일련의 활동은 종종 업데이트 압력, 복사된 논리, 개방형 시작, 제약 또는 불완전한 현장 피드백의 증상입니다.

이 지표를 정리하면 단기 예측의 신뢰성이 향상됩니다. 이는 프로젝트 팀이 실제로 준비된 작업과 단순히 현재 업데이트 날짜로 이동한 작업을 구별하는 데 도움이 됩니다. PMO 및 클라이언트 보고의 경우 데이터 날짜가 파일을 다시 계산하는 데 사용된 날짜뿐만 아니라 실제 상태 경계로 처리되었음을 보여줍니다.
