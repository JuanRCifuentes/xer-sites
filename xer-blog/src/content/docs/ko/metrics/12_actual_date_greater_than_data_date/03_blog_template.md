## 제목

Primavera P6의 데이터 날짜보다 실제 일자가 이후임

## 예상 읽기/말하기 시간

5~10분

## 목표 길이

750-1,500단어

## 청중

이 블로그는 Primavera P6 공정표 업데이트를 검증하는 스케줄러, 계획 엔지니어, 프로젝트 통제 엔지니어, 프로젝트 관리자 및 PMO 검토자를 위한 것입니다.

## 오프닝 후크

데이터 날짜는 실제 기록과 예측 사이의 선입니다. 실제 일자가 해당 행 이후에 해당하는 경우 일정은 미래와 과거를 혼합하는 것입니다.

## 소개

Primavera P6에서는 데이터 날짜가 업데이트 경계를 정의합니다. 실제 작업은 해당 날짜 또는 그 이전에 기록되어야 합니다. 그 후에도 예측 작업이 남아 있어야 합니다.

실제 시작, 실제 완료 또는 다른 실제 일자가 데이터 날짜보다 이후인 경우 일정에 상태-날짜 오류가 포함됩니다. 해당 날짜가 현재 보고 기간을 벗어나더라도 활동에 작업이 이미 시작되었거나 완료된 것으로 표시될 수 있습니다.

이 지표는 데이터 날짜보다 실제 일자가 더 큰 활동을 식별합니다. 목표는 해결되지 않은 활동이 없습니다.

## 이 매개변수의 의미

이 매개변수는 실제 일자가 현재 업데이트 주기와 일치하는지 확인합니다. 실제 일자는 데이터 날짜에 이미 달성된 실제 성과를 나타내야 합니다.

실제 일자가 데이터 날짜보다 이후인 경우 일반적으로 두 가지 중 하나가 잘못된 것입니다. 실제 일자가 잘못 입력되었거나 데이터 날짜가 승인된 보고 기간과 일치하지 않습니다.

결과가 높으면 업데이트 제한 제어가 약하거나 가져오기 문제가 있거나 실제 일자와 예측 날짜 간의 혼동이 있음을 나타냅니다.

## 이 주제가 중요한 이유

미래의 실제 일자는 공정표 신뢰성을 손상시킬 수 있습니다. 진행 상황 보고, 획득가치, 여유시간 및 마일스톤 예측이 왜곡될 수 있습니다.

또한 공정표 검토를 더 어렵게 만듭니다. PMO 검토자와 고객은 데이터 날짜가 발생한 일과 앞으로 일어날 일을 명확하게 구분할 것으로 기대합니다.

해당 경계를 준수하지 않으면 업데이트를 신뢰하기 어려워집니다.

## 나쁜 결과의 일반적인 원인

- 업데이트 마감 이후 입력된 실제 일자
- 잘못된 프로젝트 데이터 날짜
- 미래 날짜가 포함된 파일에서 진행 상황을 가져왔습니다.
- 실제 일자와 예측 날짜 사이의 혼동
- 데이터 날짜를 확인하지 않고 입력된 수동 상태 업데이트
- 공정표 업데이트 기간과 일치하지 않는 작업표 또는 현장 시스템

## 결과를 개선하는 방법

### 1. 데이터 날짜 확인

업데이트에 대해 승인된 데이터 날짜를 확인하는 것부터 시작하세요. 데이터 날짜가 잘못된 경우 활동 상태를 변경하기 전에 수정하세요.

데이터 날짜는 보고 기간 및 프로젝트 통제 절차와 일치해야 합니다.

### 2. 향후 실제 일자 검토

데이터 날짜보다 이후의 실제 일자를 필터링합니다. 실제 시작, 실제 완료, 활동 상태, 잔여 기간 및 완료율을 함께 검토합니다.

미래의 실제 일자가 잘못된 경우 수정하거나 제거하세요. 해당 작업이 데이터 날짜까지 실제로 발생하지 않은 경우에는 실제 작업으로 기록되어서는 안 됩니다.

### 3. 업데이트 워크플로 수정

문제가 가져오기에서 발생한 경우 소스 파일과 매핑을 검토하세요. 수동 업데이트로 인해 발생한 경우 업데이트 중단 절차를 강화하세요.

목표는 보고하기 전에 향후 실제 사항이 일정에 입력되는 것을 방지하는 것입니다.

## 예시 시나리오

월간 공정표 업데이트의 데이터 날짜는 5월 31일입니다. 검토 중에 스케줄러는 설치 활동의 실제 완료일가 6월 3일임을 확인합니다.

현장 보고서에는 보고 마감 이후 완료된 작업이 포함되었습니다. 스케줄러는 향후 실제 완료를 제거하고 5월 31일 현재의 올바른 상태를 복원하며 예측의 나머지 작업을 유지합니다.

이제 일정은 5월의 실제 진행 상황과 6월의 계획된 작업을 구분하므로 업데이트를 더 쉽게 신뢰할 수 있습니다.

## 권장 개선 일정

- 1일차: 지표를 실행하고 데이터 날짜를 확인합니다.
- 2~3일: 향후 실제 일자와 활동 상태를 수정합니다.
- 4~5일: 가져오기 파일을 검토하고 워크플로를 업데이트합니다.
- 6일차: 보고서, 획득가치 출력 및 마일스톤 날짜를 확인합니다.
- 7일차: 측정항목을 재평가하고 결과를 문서화합니다.

## 피해야 할 실수

미래의 실제 데이터를 숨기기 위해서만 데이터 날짜를 이동하지 마십시오. 데이터 날짜는 승인된 보고 기간을 따라야 합니다.

실제 필드 상태를 확인하지 않고 실제 일자를 삭제하지 마십시오.

수입원을 무시하지 마십시오. 향후 실제 사항이 수입에서 나온 경우 문제는 다음 주기에 반복될 수 있습니다.

## 주요 시사점

- 실제 일자는 데이터 날짜 또는 그 이전이어야 합니다.
- 목표는 해결되지 않은 활동이 없습니다.
- 향후 실제 데이터에는 잘못된 상태, 잘못된 데이터 날짜 또는 가져오기 문제가 나타날 수 있습니다.
- 날짜를 수정한 후 활동 상태, 잔여 기간 및 완료율을 수정하세요.
- 업데이트 차단 제어를 통해 반복되는 문제를 방지할 수 있습니다.

## 결론

데이터 날짜 이후의 실제 일자는 명확한 공정표 업데이트 문제입니다. 그들은 역사와 예측 사이의 경계를 모호하게 만듭니다.

이 지표를 관리하면 업데이트 규율, 진행 상황 보고, 획득가치 신뢰성, Primavera P6 공정표 제출에 대한 신뢰도가 향상됩니다.

## 행동 촉구

다음 공정표 업데이트를 발행하기 전에 데이터 날짜 이후의 모든 실제 일자를 검토하십시오. 일정이 예측 작업과 실제 성과를 명확하게 구분하도록 날짜, 상태 또는 데이터 날짜 소스 문제를 수정합니다.
