# Primavera P6의 데이터 날짜 이전 예상 완료

데이터 날짜는 발생한 일과 아직 예측된 일 사이의 경계선입니다. 클린 공정표 업데이트에서는 데이터 날짜 이전의 상태 정보를 실제 진행 상황으로 해결하고, 데이터 날짜 이후 남은 작업을 예측해야 합니다. 활동의 예상 완료 날짜가 데이터 날짜 이전인 경우 해당 경계가 흐려집니다.

이 지표는 예상 완료 시간이 현재 데이터 날짜 이전인 활동을 식별합니다. 이는 간단한 확인이지만 오래된 상태 입력, 실제 완료 누락, 오래된 현장 예측 또는 예상 날짜를 제대로 유지하지 않는 업데이트 워크플로를 드러낼 수 있습니다.

Primavera P6에서는 예상 마감이 조직의 프로세스 및 일정 설정에 따라 예측 또는 업데이트 필드로 사용되는 경우가 많습니다. 일부 팀에서는 이를 사용하여 진행 중인 활동에 대한 현장 기대치를 파악합니다. 다른 사람들은 스프레드시트나 진행 시스템에서 이를 가져옵니다. 필드는 특정 워크플로의 일정 동작에 영향을 미칠 수 있으므로 검토 없이 과거에 그대로 방치되어서는 안 됩니다.

"주 케이블 트레이 설치"라는 활동을 고려해 보십시오. 프로젝트 데이터 날짜는 3월 31일이지만 활동의 예상 완료일은 3월 24일입니다. 활동이 실제로 3월 24일에 완료된 경우 일정은 일반적으로 실제 완료 및 완료 상태가 되어야 합니다. 활동이 완료되지 않은 경우 예상 완료는 오래되었으며 최신 필드 정보를 기반으로 업데이트되어야 합니다. 어느 쪽이든 현재 값에 주의가 필요합니다.

이 문제는 팀이 데이터 날짜를 앞당기지만 모든 예측 필드를 완전히 업데이트하지 않을 때 자주 나타납니다. 완료율이 업데이트될 수 있습니다. 잔여 기간은 조정될 수 있습니다. 일부 실제 일자가 입력될 수 있습니다. 그러나 이전 업데이트의 예상 마감 값은 그대로 유지됩니다. 결과는 부분적으로 업데이트된 것처럼 보이지만 여전히 과거의 예상 완료 날짜를 포함하는 일정입니다.

첫 번째 질문은 데이터 날짜가 올바른지 여부입니다. 데이터 날짜가 잘못 설정된 경우 메트릭이 잘못된 경계에 플래그를 지정할 수 있습니다. 데이터 날짜가 확인되면 각 활동을 실제 상태와 비교하여 검토해야 합니다. 데이터 날짜 이전에 활동이 완료되었습니까? 실제 마무리가 누락되었나요? 아직도 활동이 활발합니까? 잔여 기간은 여전히 ​​남은 작업을 나타냅니까?

완료된 작업의 경우 일반적으로 실제 완료를 입력하거나 수정한 다음 활동 상태, 완료율 및 잔여 기간이 일치하는지 확인하는 것이 수정 방법입니다. 아직 진행 중인 작업의 경우 예상 완료 날짜는 데이터 날짜 또는 그 이후의 유효한 날짜로 업데이트되어야 합니다. 공정표 계산에 현재 예측이 반영되도록 잔여 기간도 검토해야 합니다.

시작되지 않은 작업의 경우 데이터 날짜 이전의 예상 완료는 일반적으로 이전 값 또는 가져온 값을 나타냅니다. 스케줄러는 활동이 여전히 계획에 속하는지, 예측 날짜를 다시 계산해야 하는지, 프로젝트 업데이트 절차에 따라 예상 날짜를 제거하거나 교체해야 하는지 확인해야 합니다.

P6의 실제 검토에는 활동 ID, 활동 이름, WBS, 활동 상태, 예상 완료, 실제 시작, 실제 완료, 잔여 기간, 완료율, 시작, 완료, 총 부동 및 달력이 포함되어야 합니다. 팀은 중요하고 거의 중요한 활동, 인수인계 작업, 고객 대면 이정표 및 단기 예측 활동의 우선순위를 지정해야 합니다.

이 측정항목은 프로세스 문제를 파악하는 데도 도움이 됩니다. 업데이트할 때마다 동일한 문제가 나타나면 소스는 가져오기 파일, 스프레드시트 템플릿 또는 현장 보고 워크플로일 수 있습니다. 팀은 일정이 계산되어 발행되기 전에 예상 완료가 다른 시스템에서 로드되고 있는지 확인하고 유효성 검사 규칙이 존재하는지 확인해야 합니다.

목표 임계값은 해결되지 않은 활동이 없어야 합니다. 그렇다고 표시된 모든 활동이 주요 문제라는 의미는 아닙니다. 이는 모든 활동이 수정되거나 설명되어야 함을 의미합니다. 데이터 날짜 이전의 예상 완료 시간은 단순히 아무도 확인하지 않는다는 이유만으로 일정에 남아 있어서는 안 됩니다.

이 지표를 정리하면 공정표 신뢰성이 향상됩니다. 이는 팀이 명확한 업데이트 경계를 유지하고 실제 성과를 예측 작업과 구별하며 오해의 소지가 있는 예측 또는 부동 결과를 방지하는 데 도움이 됩니다. PMO 검토에서는 공정표 업데이트가 계산된 것뿐만 아니라 실제로 상태 일관성을 확인했음을 보여줍니다.
