# 상태가 완료되지 않았지만 작업 잔여 기간이 0입니다.

잔여 기간은 Primavera P6 업데이트에서 가장 중요한 상태 필드 중 하나입니다. 활동을 완료하는 데 아직 필요한 시간을 일정에 알려줍니다. 일반 작업 활동의 잔여 기간이 0인 경우 메시지는 간단합니다. 수행할 시간이 남아 있지 않다는 것입니다. 동일한 작업이 완료로 표시되지 않으면 일정은 두 가지 다른 스토리를 동시에 전달하는 것입니다.

이 지표는 잔여 기간이 0이지만 작업 상태가 완료되지 않은 작업 활동을 식별합니다. 작업 활동은 이러한 불일치가 작업 계획, 진행 보고, 획득가치 및 예측 검토에 직접적인 영향을 미칠 수 있기 때문에 더 광범위한 상태 품질 검사의 집중 버전입니다.

일반적인 작업의 경우 잔여 기간이 0이라는 것은 일반적으로 작업이 완료되었음을 의미합니다. 활동에는 실제 완료, 완료 상태 및 프로젝트 업데이트 절차와 일치하는 진행 값이 있어야 합니다. 작업이 여전히 진행 중이거나 시작되지 않은 경우 일정량의 작업이 여전히 예상되므로 일반적으로 잔여 기간은 0보다 커야 합니다.

이 문제는 바쁜 업데이트 주기 중에 자주 나타납니다. 현장 팀은 활동이 효과적으로 완료되었음을 보고할 수 있으므로 스케줄러는 잔여 기간을 0으로 줄이지만 실제 완료를 입력하지 않습니다. 가져오기 파일은 활동 상태를 업데이트하지 않고 잔여 기간을 업데이트할 수 있습니다. 수동 업데이트는 진행률 값을 설정하지만 활동을 잘못된 상태로 둘 수 있습니다. 그 결과 기간 관점에서는 완료된 것처럼 보이지만 상태 관점에서는 완료되지 않은 작업이 생성됩니다.

그 불일치가 중요합니다. 잔여 기간이 없는 작업은 향후 작업이 예상대로 진행되지 않을 수 있습니다. 공식적으로 완료되지 않은 경우에도 미리보기에서 사라질 수 있습니다. 진행과 완료가 일치하지 않으면 획득가치 보고가 왜곡될 수 있습니다. 또한 일정이 작업 완료 여부를 명확하게 답변할 수 없기 때문에 클라이언트 또는 PMO 검토 중에 혼란을 야기할 수도 있습니다.

검토는 간단한 P6 레이아웃부터 시작해야 합니다. 활동 ID, 활동 이름, WBS, 활동 유형, 활동 상태, 실제 시작, 실제 완료, 원래 기간, 잔여 기간, 완료 기간, 완료율 유형, 활동 완료율, 시작, 완료 및 총 부동 시간을 포함합니다. 잔여 기간이 0이고 활동 상태가 완료되지 않은 작업 활동을 필터링합니다.

플래그가 지정된 각 작업은 담당 소유자와 함께 검토해야 합니다. 실제로 작업이 완료된 걸까요? 그렇다면 작업은 일반적으로 완료로 표시되고 올바른 실제 완료가 제공되어야 합니다. 스케줄러는 또한 완료율과 잔여 기간이 프로젝트의 진행 규칙과 일치하는지 확인해야 합니다.

작업이 완료되지 않은 경우 수정 방법이 다릅니다. 작업은 진행 중 또는 시작되지 않음과 같은 올바른 상태를 유지해야 하지만 잔여 기간은 유효한 값으로 복원되어야 합니다. 해당 값은 목표 완료 날짜나 보고 기본 설정이 아니라 데이터 날짜를 기준으로 남은 작업 시간을 반영해야 합니다.

"화재 경보 장치 설치"라는 작업을 고려해 보십시오. 현장 보고서에는 설치가 거의 완료되었다고 나와 있으며 스케줄러는 잔여 기간을 0으로 설정합니다. 그러나 테스트 결과 여러 장치에서 여전히 수정이 필요하고 활동이 데이터 날짜까지 실제로 완료되지 않은 것으로 나타났습니다. 이 경우 작업은 잔여 기간이 0인 상태로 남아 있어서는 안 됩니다. 일정이 완료되지 않은 작업을 계속 예측할 수 있도록 남은 노력을 추정하고 입력해야 합니다.

이제 "레벨 3 슬래브 타설"이라는 작업을 고려해보세요. 콘크리트 타설이 데이터 날짜 이전에 완료되었지만 활동이 여전히 진행 중으로 표시되고 실제 완료가 없습니다. 여기서 Remaining Duration인 0은 아마도 정확할 것입니다. 그러나 상태 업데이트는 불완전합니다. 스케줄러는 실제 완료를 입력하고 작업을 완료로 표시해야 합니다.

이 측정항목의 목표 임계값은 해결되지 않은 작업 활동이 없어야 합니다. 해결되지 않았다는 단어가 중요합니다. 일부 항목은 수정 전 현장 확인이 필요할 수 있지만 보고 일정에 설명되지 않은 상태로 남아 있어서는 안 됩니다. 임시 업데이트 사유가 있는 경우 각 항목을 수정하거나 소유자에게 할당하거나 문서화해야 합니다.

이 지표는 업데이트 규칙을 개선하는 데도 도움이 됩니다. 매 주기마다 동일한 문제가 나타나면 팀은 일정 문제 발생 전에 가져오기 매핑, 업데이트 양식, 현장 보고 지침 및 확인 사항을 검토해야 합니다. 사용자는 활동을 제대로 완료하지 않고도 진행 상황을 표시하는 가장 빠른 방법인 것처럼 느끼기 때문에 잔여 기간을 0으로 설정할 수 있습니다.

이 측정항목을 정리하면 일정을 더 쉽게 신뢰할 수 있습니다. 잔여 기간, 활동 상태, 실제 완료일 및 진행률 값을 정렬합니다. 더 중요한 것은 프로젝트 팀이 실제로 완료된 작업과 여전히 주의가 필요한 작업에 대해 더 나은 결정을 내리는 데 도움이 된다는 것입니다.
